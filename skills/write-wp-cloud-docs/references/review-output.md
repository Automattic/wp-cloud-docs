# Review output

Review findings are an exception list. Do not create extra review files unless the user asks for one.

Report findings in this order:

1. Required fixes: factual contradictions, actor or ownership errors, broken instructions or links, security or privacy exposure, missing critical warnings, and loss of useful source material.
2. Owner or technical decisions: one concrete question for each claim that cannot be resolved from available evidence.
3. Recommended revisions: material clarity, structure, retrieval, or maintenance improvements that need judgment, including formulaic filler, invented jargon, obscured actors, and instructions whose complexity hides a condition or action.

For each finding, include the document key or title, the affected heading, the exact concern, and the smallest safe next action. Quote only the minimum text needed to identify the problem. Do not copy credentials, private URLs, customer identifiers, or long private passages.

Treat it as an actor or ownership error when a draft presents partner and client-host terms as different organizations, gives a downstream customer a WP Cloud account or direct API access, or assigns customer identity, site mapping, downstream access control, or downstream billing to WP Cloud instead of the partner.

Treat sentence length, semicolons, and phrase matches as review signals, not findings by themselves. Report them only when they obscure an actor, action, prerequisite, state, limit, warning, or reader outcome. Do not report an exact technical term or an isolated wording preference as a problem.

Describe the observable wording problem and its effect on the reader. Do not score a document or infer whether AI wrote it.

Omit unchanged claims, routine wording preferences, formatting nits, and generic praise. Never record approval that the owner did not give.
